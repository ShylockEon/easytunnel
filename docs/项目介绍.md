# EasyTunnel 项目介绍

> English version: [Project Introduction (English)](project-introduction.en.md)

> 一个把内网服务安全地"搬"到公网的自托管工具：**一台公网服务器 + 一个单文件客户端 + 一个网页控制台**。
> 不装依赖、不写配置文件、改映射不用重启。

---

## 1. 这是什么

EasyTunnel 是一套轻量的内网穿透系统，用来把内网机器上的服务（Web 站点、SSH、数据库、远程桌面等）暴露到公网访问。

它由三部分组成：

| 组件 | 位置 | 形态 |
|---|---|---|
| 服务端 | 任意有公网 IP 的机器 | 单个 `server.js`（Node.js 标准库，零第三方依赖，可 Docker 运行） |
| 客户端 | 内网 Windows 机器 | 单个 `EasyTunnelClient.exe`（约 84 MB，内置 Node 运行时，免安装） |
| 管理控制台 | 浏览器 | 服务端内置的暗色 Web 页面（端口映射、路径映射、客户端、流量统计） |

典型用途：在办公室电脑上跑一个内部系统，出差时通过公网域名/端口访问；或者把家里的 NAS、开发机 SSH 临时开放给外部。

---

## 2. 为什么做这个

常见的穿透方案各有取舍：

- **frp** 功能全、性能好，但要手写 `frpc.toml`，加一条映射就得改配置、重启进程；
- **Cloudflare Tunnel** 免服务器，但依赖域名托管和公网 HTTP，国内速度一般；
- **商业内网穿透**（cpolar、natapp 等）上手最快，但免费档限速限量，配置在厂商后台；
- **Tailscale/ZeroTier** 是组网，不是把端口发布到公网。

EasyTunnel 的目标很明确：**在有公网服务器的前提下，把"加映射"变成网页上点两下的事**，并且客户端零安装、单文件可分发。为此它做了三件事：

1. 映射全部存在服务端，网页增删改**立即生效**（服务端按需增删端口监听、断开存量连接）；
2. 客户端只有一个可执行文件，双击出现配置窗口，连上后最小化到托盘；
3. 多台内网机器可以**同时在线**，各自独立令牌、映射指定归属，互不干扰。

## 3. 核心特性

**配置与运维**

- 网页即配置：端口映射、HTTPS 路径映射、服务端地址、客户端令牌都在管理页维护
- 添加/修改映射使用弹窗表单，回车提交，保存即生效，无需重启服务或客户端
- 多客户端管理：添加、重命名、重置令牌、删除、复制该客户端配置
- 配置持久化在 `config.json`，迁移与重启不丢；旧版单客户端配置自动迁移

**转发能力**

- TCP 端口映射：HTTP / HTTPS 站点、SSH、MySQL、Redis、RDP 等任意 TCP 服务
- HTTPS 路径映射：与管理端口共用，按首字节分流 TLS / 明文，按路径前缀转发到不同内网服务（可选去掉前缀、可选校验上游证书）
- keep-alive 连接复用：同一公网连接上连续请求可复用通道，大文件不截断
- 背压控制：`pause/resume` 双向流控，慢速内网服务不会把内存打爆；暂存上限 1 MB

**可靠性**

- 帧协议多路复用：一条控制连接承载所有映射通道
- 心跳与自愈：客户端每 5 秒 ping，40 秒无响应主动重连；服务端 30 秒无任何帧判定离线并清理通道
- 断线自动重连，退避策略（前两次 200 ms，之后逐步拉长到 10 秒）
- 映射状态实时可见：`运行中 / 已停用 / 异常 / 等待客户端`

**性能**

- 数据帧零拷贝发送：帧头与负载两次 write + `cork/uncork` 合并，省掉每块数据的整段拷贝
- 分片队列解码器：整帧落在同一 socket chunk 内时零拷贝切片，跨 chunk 只拷贝一次
- 实测（本机 loopback）：解码吞吐从约 1.1 GB/s 提升到 6.5 GB/s（耗时降 83%）；隧道 20 MB 传输 318–408 MB/s

**安全**

- 管理页与全部管理 API 需要管理密码；登录失败同 IP 连续 5 次锁定 60 秒
- 每个客户端独立令牌，认证按令牌识别归属；密码/令牌比较使用恒定时间算法
- 管理端口 9000 与隧道端口 9001 可分离，必要时只对可信来源开放
- 自签 HTTPS 证书可下载安装（路径映射用）

## 4. 工作原理

### 4.1 一次外网请求的链路

```
浏览器/客户端
   │  访问 http://公网IP:18080
   ▼
服务端 server.js
   │  ① 18080 端口监听器接受连接，查到映射：18080 → 127.0.0.1:8080，归属"机器A"
   │  ② 在该客户端的控制连接上发 {t:'open', host, port}，分配通道号 ch
   ▼
内网客户端 EasyTunnelClient.exe（机器A）
   │  ③ 连接本机 127.0.0.1:8080，成功后回 {t:'ready', ch}
   │  ④ 双向转发：公网数据 → 本机服务；本机响应 → 公网连接
   ▼
内网服务（如本地 Web）
```

### 4.2 帧协议

所有流量复用一条 TCP 控制连接，帧头固定 9 字节：

```
| type(1) | channelId(4, 大端) | length(4, 大端) | payload(length) |
```

- `type=1`：控制帧，JSON（UTF-8）
- `type=2`：数据帧，原始字节

控制消息包括：`auth / auth_ok / err / open / ready / close / pause / resume / ping / pong`。

### 4.3 关键设计

- **通道即连接**：每条公网连接一个通道号，服务端与客户端各自维护本地 socket 映射
- **软关闭**：内网 socket 关闭不等于公网连接关闭，保留通道 60 秒等待 keep-alive 复用，避免尾部数据被 RST 丢弃
- **统一背压**：任一侧写缓冲满时发 `pause`，对端停止读取；`drain` 后发 `resume`，并有超时兜底自动恢复
- **多客户端隔离**：连接池 `clients: Map<clientId, conn>`，通道记录归属连接，映射按 `clientId` 路由

## 5. 管理控制台

- **隧道状态**：在线/离线、当前客户端、在线时长、隧道端口、服务地址
- **实时流量**：近 60 秒上下行曲线、峰值、逐映射速率条
- **映射列表**：公网地址、目标客户端、内网地址、状态、连接数、上下行速率与累计流量
- **客户端**：在线状态、IP、映射数、活跃连接；添加 / 重命名 / 重置令牌 / 删除 / 复制配置
- **路径映射**：HTTPS 路径、内网协议与端口、是否去前缀、是否校验上游证书
- **服务端设置**：公网地址、隧道端口、客户端配置下发
- **HTTPS 证书**：状态、主题、有效期，支持下载证书

添加/修改映射为弹窗表单（支持回车提交、Esc 或点遮罩关闭）；删除与重置令牌使用「再点一次确认」，避免误操作。

## 6. 快速开始

### 6.1 服务端

```bash
cd server
cp config.example.json config.json        # 首次也可直接启动，自动生成密码/令牌
docker compose up -d                      # 或：node server.js
docker compose logs easytunnel            # 查看管理密码与客户端令牌
```

访问 `http://<公网IP>:9000`，用管理密码登录。

> `docker-compose.yml` 使用 `network_mode: host`：映射端口在网页里随时新增，容器直接监听宿主机端口，加端口不用改 compose。
> 安全组/防火墙需放行 9000、9001 以及每条映射的公网端口。

### 6.2 客户端

管理页「客户端」→ 选择客户端 →「复制配置」，把得到的 `client.json` 与 `EasyTunnelClient.exe` 放同一目录，双击运行。
连接成功后窗口显示「已连接」，可最小化到托盘常驻。

多台机器各自使用自己的配置，互不顶替。

### 6.3 添加映射

「映射列表」→「添加映射」：选择目标客户端（或「自动」），填公网端口 → 内网 `127.0.0.1:端口`，保存即刻生效。
外网访问 `http://<公网IP>:<公网端口>` 即到达目标机器上的服务。

## 8. 部署与运维

- **发版**：备份 `server.js` / `admin.html` / `config.json` → 上传覆盖 → `docker compose restart`（源码挂载，无需重建镜像）
- **回滚**：备份文件覆盖回去再重启即可
- **配置**：`config.json` 保存管理密码、客户端列表与令牌、映射、公网地址、HTTPS 开关；首次启动自动生成
- **日志**：容器 `docker compose logs`；客户端同目录 `client.log`（异步批量落盘，避免转发路径写盘）
- **注意**：启动日志会打印管理密码与各客户端令牌，注意日志访问权限

## 9. 安全说明

- 隧道控制端口是**明文 TCP + 令牌认证**，公网暴露时请使用强令牌，并尽量限制来源 IP
- 管理端口建议限制来源（安全组白名单 / VPN），不要直接对全网开放
- 自签 HTTPS 证书只用于路径映射，首次访问需在浏览器确认
- 令牌等同账号权限：泄露后可在管理页「重置令牌」，只影响该客户端

## 12. 常见问题

**Q：映射显示「等待客户端」？**
目标客户端离线。检查该机器的 exe 是否在运行、令牌是否匹配、网络是否可达 9001 端口。

**Q：外网访问超时，但服务端日志没有请求？**
大概率是云安全组/防火墙没放行该公网端口。先确认端口监听正常，再检查安全组白名单。

**Q：一台客户端能配多少条映射？**
没有硬限制，受限于端口与内存；每条映射独立监听、独立统计。

**Q：客户端会不会被杀后台？**
Windows 客户端可最小化到托盘常驻；Linux/服务端场景建议用 `--no-gui` 配合系统服务管理器。

**Q：大文件下载会被截断吗？**
不会。keep-alive 软关闭 + 背压控制保证尾部数据完整，已用 300 KB / 20 MB 实测。
